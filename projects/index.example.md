# Project selection

Copy this template to local `projects/index.md`. Actual index/profiles are private source configuration, ignored by Git; installed copies are generated and must not be edited. This empty table selects no projects. Add one row per project after copying `project.example.md` to a meaningful filename and replacing its placeholders. See `docs/setup.md` in the source clone for onboarding.

| Profile | Explicit names / aliases | Git host and repository | Jira prefix hint | Optional exact local root |
| --- | --- | --- | --- | --- |

Row shape (illustrative only): `| my-project.md | <PROJECT-ALIAS> | github.example.com/<org>/<repository> | ABC | (unset) |`. Filenames are arbitrary; the index owns identity mapping. Use a plain filename or single-backtick filename in the first cell, directly under `projects/`, with a lowercase `.md` extension. Prefer lowercase kebab-case without spaces. No subdirectories, path traversal, Windows-reserved names, `index.md`, `README.md`, or `.example.md` templates. Use exact spelling on every machine; case/Unicode aliases are rejected. Keep this one five-column table, including its header and leading/trailing pipes; no Markdown links or embedded pipes in cells. Repeated identical profile references install once; avoid duplicate rows when mapping aliases.

1. For code or PR work, inspect the actual session directory using `git rev-parse --show-toplevel` and `git remote -v`. Use the app's session worktree, which may differ from the original checkout. Compare full host/owner/repository identities, not folder names or substrings. Normalize HTTPS and SSH forms, remove a trailing `.git`, and ignore credential components. Resolve SSH host aliases with Git/SSH configuration when necessary. Never display embedded credentials.
2. A unique matching remote selects the profile. Multiple matching projects, an explicit project that conflicts with the repository, or a ticket prefix that conflicts with it require clarification. A prefix is a cross-check, never sufficient evidence to redirect a PR to another repo or Jira site. Do not query alternate Jira sites to find a ticket by trial and error.
3. If no remote matches, an exact configured local root may identify an offline checkout. If source lists labeled Windows/macOS roots, use only the current machine's entry. Normalize paths for the OS, compare the Git root (not a subdirectory), and resolve links. A known conflicting remote overrides this fallback and must be resolved. An unknown remote may be a fork; inspect its upstream or ask rather than inventing a mapping.
4. For a story explicitly requested for another project, select that project for the story and say so. Do not use the current checkout's code as the other project's evidence. Otherwise use the uniquely resolved current repo. Outside a repository, a unique explicit project alias is enough for story drafting. Ambiguous or missing identity means ask one targeted question.
5. Read exactly one selected profile relative to this index. Do not open the others or any templates. Re-read on a target change, after compaction if the selection evidence is missing, and before an approved write. Use a new session when moving between projects so old profile content is not retained in conversation history.

An empty index or missing selected profile blocks live project-dependent actions. Profiles marked `UNCONFIGURED` permit illustrative drafts only. Do not contact placeholder hosts, run example commands, select placeholder reviewers, or execute writes. Fill in real facts and change each profile's status to `READY` after checking them. Missing required facts block the dependent action, not unrelated local work. Keep credentials in the host/tool configuration, never in profiles.
